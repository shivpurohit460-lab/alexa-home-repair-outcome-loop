## Audit findings and repairs

### 1. AgentCore audit-trace isolation — REPAIRED

**Finding:** the AgentCore adapter stored tool evidence in one mutable module-level list. Concurrent invocations in the same runtime process could interleave and contaminate each other's audit traces.

**Repair:** replaced the shared list with invocation-local `ContextVar` state and immutable tuple updates.

**Original-failure regression:** added a forced two-thread interleaving test using a barrier. The test requires each invocation to receive only its own `create_repair_case` and `book_home_service` events and arguments.

**Re-audit:** CI PASS.

### 2. Alexa+ MCP protocol evidence — REPAIRED

**Finding:** the repository had a real Streamable HTTP round-trip test but did not explicitly assert the negotiated MCP protocol revision required by the hackathon.

**Repair:** the HTTP integration regression now asserts:

```python
initialize_result.protocolVersion >= "2025-11-25"
```

Because MCP protocol revisions use ISO-style dates, lexical ordering preserves chronological ordering for this format.

**Re-audit:** CI PASS.

### 3. GitHub Actions authority / supply-chain provenance — REPAIRED

**Finding:** CI token permissions were implicit and workflow actions were referenced through mutable major-version tags.

**Repair:**

- CI now declares `contents: read`.
- checkout does not persist credentials.
- GitHub Actions used by CI and Pages are pinned to immutable commit SHAs.
- Pages retains only the permissions required to publish the judge simulator.

**Re-audit:** workflow syntax and project CI PASS on the repaired branch.

### 4. Dependency and deployment-tool reproducibility — REPAIRED

**Finding:** the Python project allowed broad direct dependency ranges and the Gate 5B script installed the latest AgentCore/CDK CLIs at execution time. A dependency/tool release between audit and judging could change behavior without any repository commit.

**Repair:**

- direct Python dependencies are pinned to the versions resolved by the successful 21 Sep CI baseline;
- CI now exercises both Python 3.11 (the Docker/local floor) and Python 3.13 (the AgentCore target);
- Gate 5B pins `@aws/agentcore@0.30.0` and `aws-cdk@2.1142.0` instead of installing mutable latest tags.

**Re-audit:** both Python 3.11 and Python 3.13 matrix jobs PASS after the pins.

### 5. AWS deployment identity — REPAIRED IN CODE / OWNER SETUP STILL REQUIRED

**Finding:** fresh read-only AWS evidence showed the identity available to the audit resolved to the AWS account root identity. MFA is enabled and no root access keys are present, but application deployment from root violates least-privilege discipline.

**Repair:** Gate 5B now fails closed before Bedrock validation or AgentCore deployment if the caller ARN is root. A scoped IAM deployment role/user is required.

**Re-audit:** fail-closed ordering is covered by regression and CI PASS.

### 6. AWS provider-state drift — RECONCILED

Fresh 21 Sep provider evidence shows:

- AWS identity lookup succeeds.
- Bedrock foundation-model and inference-profile listing succeeds.
- `global.anthropic.claude-sonnet-4-6` is ACTIVE.
- AgentCore control-plane listing succeeds.
- zero AgentCore runtimes are currently deployed.
- a bounded Bedrock `Converse` probe still fails with an AWS account-verification `AccessDeniedException`.

Therefore the correct state is:

**control-plane access partially restored; live model inference remains verification-blocked; AgentCore deployment remains unproven.**

Documentation was corrected so catalog visibility cannot be mistaken for live inference proof.

### 7. Default-branch governance — OPEN OWNER/ADMIN GATE

`main` is currently unprotected and no repository ruleset is active. Because GitHub Pages deploys automatically from `main`, an accidental direct push can bypass PR/CI discipline.

Tracked separately in GitHub Issue #10.

Required before final submission:

- require pull requests to `main`;
- require CI;
- block force-push/deletion;
- keep public judge access intact.

This ARRA did not pretend to repair a control unavailable through the connected administration surface.
